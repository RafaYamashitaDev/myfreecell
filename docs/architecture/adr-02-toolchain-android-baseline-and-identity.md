# ADR-02: Toolchain, Android baseline, orientation, and application identity

Status: Accepted

Date: 2026-11-06

## Context

Scaffolding needs an approved Flutter channel, Android API baseline, launch orientation, and application ID. Version one is landscape-only and should support both landscape directions, as defined in the [product specification](../product/product-spec.md). The framework choice is [ADR-01](adr-01-framework-and-platform-targets.md).

## Decision

- Use the Flutter stable channel.
- Record the exact Flutter version and bundled Dart version selected during scaffolding.
- Do not introduce FVM initially.
- Use Android API 36 as the target API baseline.
- Use API 36 or a newer compile API if required by the selected stable Flutter toolchain.
- Retain Flutter’s generated supported minimum API initially, then verify and record its concrete value during scaffolding.
- Support both landscape directions.
- Configure landscape orientation natively for launch and request both landscape orientations through Flutter before UI rendering.
- Later verify Android large-screen, foldable, and multi-window orientation behavior.
- Use `com.groovoodoo.myfreecell` provisionally as the Android application ID and namespace for scaffolding and development.
- That identifier is not legally or commercially finalized.
- Trademark and domain clearance are required before creating the permanent Google Play listing.
- Flutter SDK and target-SDK upgrades are explicit maintenance changes requiring build and test verification.

## Consequences

- `com.groovoodoo.myfreecell` may be used for scaffolding and development. It is provisional and is not the finalized store identity.
- The permanent Google Play listing waits on trademark and domain clearance.
- The concrete minimum API is the value generated by the selected Flutter toolchain, verified and recorded during scaffolding, not a number chosen here.
- A later Flutter SDK or target-SDK upgrade is a deliberate maintenance change and requires build and test verification.

## Deferred or not decided

Signing, permanent store identity, platform backup behavior, and the concrete minimum API remain deferred.
